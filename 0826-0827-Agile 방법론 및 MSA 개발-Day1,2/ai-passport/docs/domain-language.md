# AgentPass 도메인 언어 규격

## 1. 핵심 흐름

AgentPass의 사용자 흐름은 아래 다섯 단계로 표현한다.

`미션 등록 → 권한 설계 → Passport 발급 요청 → 발급 검토 → Passport 발급`

화면 제목, 버튼, 상태, 알림에서 이 순서를 벗어난 동의어를 만들지 않는다.

## 2. 표준 용어

| 표준 용어 | 의미 | 사용하지 않는 표현 |
| --- | --- | --- |
| 미션 | Agent에게 맡길 하나의 업무 단위 | 업무 요청, 요청 업무, 작업 |
| 미션 보드 | 미션 목록과 상태를 확인하는 화면 | 내 업무 요청, 업무 요청 목록 |
| 미션 등록 | 미션 내용을 저장하는 행동 | 업무 요청 완료, 요청 저장 |
| Agent | 미션을 수행하는 실행 주체 | 에이전트, 추천 Agent |
| 권한 설계 | 미션에 필요한 최소 권한을 정하는 단계 | 권한 분석, AI 분석 |
| 권한 제안 | 권한 설계 결과로 제시된 권한 목록 | 최소 권한 분석 결과 |
| Passport | Agent가 정해진 기간 동안 사용할 권한 묶음 | 권한 Passport, 패스포트 |
| 발급 요청 | Passport 검토를 요청하는 행동 | Passport 신청, 승인 요청 |
| 발급 검토 | 관리자가 발급 여부를 판단하는 단계 | 관리자 승인, 승인 검토 |
| 발급 완료 | 검토를 통과해 Passport가 활성화된 상태 | 승인 완료 |
| 검토 대기 | 발급 검토가 시작되기 전 또는 진행 중인 상태 | 승인 대기 |
| 반려 | 발급 요청이 거절된 상태 | 승인 실패 |
| 크레딧 | 권한 설계에 사용하는 단위 | credits, 분석 크레딧 |

API 필드명과 서버 상태 코드는 변경하지 않는다. 이 규격은 사용자에게 보이는 문구에 적용한다.

## 3. 이름과 대소문자

- `AgentPass`, `Agent`, `Passport`는 항상 이 표기를 사용한다.
- `미션`, `권한`, `크레딧`은 한글로 표기한다.
- 영문 대문자만 사용한 eyebrow는 화면의 성격을 나타내는 짧은 이름으로 제한한다.
- 한 문장 안에서 `에이전트/Agent`, `패스포트/Passport`, `credit/크레딧`을 혼용하지 않는다.

## 4. 문장 원칙

- 제목은 명사형 또는 짧은 행동형으로 쓴다: `미션 보드`, `새 미션 만들기`.
- 설명은 존댓말 권유형 대신 현재형으로 쓴다: `미션과 권한 설계 상태를 확인합니다.`
- 버튼은 결과가 분명한 동사형으로 쓴다: `권한 설계 시작`, `발급 요청`, `미션 수정`.
- 상태는 명사형으로 쓴다: `설계 중`, `검토 대기`, `발급 완료`.
- 완료 알림은 `대상 + 결과` 순서로 쓴다: `Passport 발급 요청을 취소했습니다.`
- `~했어요`, `~할게요`, `~해주세요`처럼 대화체인 표현은 사용하지 않는다.
- `안전하게`, `간편하게`, `정확하게`처럼 근거 없는 수식어는 필요한 경우에만 사용한다.

| --- | --- |
| 사용자 첫 화면 | 미션 보드 |
| 미션 생성 화면 | 새 미션 만들기 |
| 권한 결과 화면 | 권한 설계 결과 |
| Passport 목록 | Passport |
| 크레딧 화면 | 크레딧 |

## 6. 상태 체계

### 권한 설계

- 설계 대기
- 설계 중
- 설계 완료
- 설계 실패

### Passport

- 미발급
- 검토 대기
- 사용 가능
- 반려
- 만료

### 관리자 처리

- 검토 대기
- 발급 완료
- 반려
